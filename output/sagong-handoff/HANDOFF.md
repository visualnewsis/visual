## 먼저 읽기

프로젝트 정책은 저장소 최신 `AGENTS.md`가 단일 원본이다. 작업 시작 전 이를 읽고 Git 상태와 최신 main을 확인한다. 이 문서는 정책을 대체하지 않으며, 공용 파일 수정·배포 승인을 뜻하지 않는다. 사용자가 맡긴 실제 게임 파일을 찾아 기존 구현에 최소 변경으로 적용한다. localhost:8901의 서비스 폴더는 아직 확인하지 못했다. 현재 저장소 검색에서는 ‘사공팡팡’과 `btnStart`가 발견되지 않았으므로 새 폴더나 서비스 주소를 추정하지 말 것.

## 1. 사용자 의도

## 3. 가장 중요한 방향

**쌓이면 배가 산으로 올라간다 → 같은 색을 연결해 터뜨린다 → 연쇄로 많은 사공을 지우면 배가 시원하게 내려온다.**

사용자는 처음 생성한 산길 배경을 긍정적으로 평가했다. **`assets/mountain-path-background.png`를 우선 디자인안으로 사용한다.** 영상의 상단 풍경 / 하단 수중 보드 구성은 현재 구현을 설명한 것이지 유지해야 하는 확정 요구가 아니다. 산길 배경을 살리기 위해 화면 배치를 조정할 수 있다. 단, 퍼즐판 자체를 산비탈처럼 회전시키거나 움직이지 않고 논리 좌표·기존 조작·규칙을 보존한다.

권장 구성: 중앙의 조용한 영역에 반투명 짙은 청록색 퍼즐판을 두고, 오른쪽 산길에는 배의 상승·하강 경로를 둔다. 배는 하단 강에서 우측 정상으로 올라간다. 이것은 시각 배치 제안이며, 실제 좁은 화면에서는 배가 판을 가리지 않는지 먼저 확인한다. 산길과 판을 모두 작게 줄이기보다 판의 터치 크기를 우선한다. 배경의 장식 지형과 실제 판정은 분리한다.

사공이 물에 빠져 고통받는 연출 대신, 둥근 게임 말과 반짝임으로 가볍게 표현한다. 원작의 캐릭터·로고·음악을 사용하지 않는다.

## 4. 구현 우선순위

### P0 — 현재 규칙 검증 및 명료화

기존 연결 판정, 중력, 연쇄, 점수, 종료 판정을 먼저 읽고 보존한다. 같은 색 연결은 상하좌우이며 대각선은 제외하는 방향을 권장한다. 연결 그룹 4명 이상을 같은 단계에서 함께 제거하고, 낙하 정리가 끝난 후 다음 연결을 검사한다. 동시에 두 그룹이 사라지는 것과 중력 이후 발생하는 다음 연쇄를 구분한다.

해결 중인 연쇄가 끝나기 전에 배가 잠깐 위험선을 넘었다는 이유로 종료하면 역전 기회를 빼앗는다. 종료 판정은 안정된 보드 상태에서 수행하는 방향을 권장하되, 기존 설계와 다르면 사용자에게 차이를 설명한다.

### P1 — 배 높이와 위기의 관계를 분명히

기존 배 높이 계산이 있으면 그것을 우선 사용한다. 높이 규칙이 없다면 첫 제안은 `위험도 = 가장 높은 정착 열 높이 / 사용 가능한 보드 높이`이며 0~1로 제한한다. 이동 중인 쌍과 착지 그림자는 제외한다. 실제 보드 크기를 확인한 뒤 적용하고 임의로 6×12 등으로 교체하지 않는다.

배의 목표 위치는 위험도와 연결하고, 실제 표시 위치만 부드럽게 보간한다. 상승은 약 250~400ms, 제거 후 하강은 약 350~600ms를 초기 실험값으로 삼는다. 연쇄마다 현재 정착 상태를 반영하되 화면 떨림이 누적되지 않게 한다.

주의: 최고 열 기준이면 낮은 열을 지워도 배 높이가 안 내려갈 수 있다. 이는 정상적인 계산 결과다. ‘지울 때마다 반드시 하강’하는 경험을 원하면 기존의 사공 수 기반 계산을 검토해야 한다. 시각 효과만을 위해 실제 위험도와 불일치하는 영구 하강 보너스를 넣지 않는다.

배는 수면에서 산 정상으로 이동하는 명확한 경로를 따른다. 정상에 가까워질수록 약한 기울기·표정·경고색으로 위기를 전달한다. 색만으로 알리지 않고 “정상까지 얼마 안 남았어요” 같은 짧은 상태 안내를 보조로 사용할 수 있다. 안내는 플레이를 가리지 않는다.

### P2 — 연쇄의 손맛

- 제거 직전 약 100ms 강조 → 짧은 팝 → 중력 낙하 → 다음 연결 확인.
- 제거 말이 살짝 커졌다가 사라지고 제공된 반짝임을 짧게 사용한다.
- ‘2연쇄’, ‘3연쇄’ 글자는 HTML/Canvas 텍스트로 표시한다. 이미지에 구워 넣지 않는다.
- 큰 연쇄에서는 배 하강과 짧은 물결로 구출감을 만든다. 전체 보드를 크게 흔들지 않는다.
- reduced motion에서는 흔들림과 과한 확대를 생략한다. 소리는 추후 별도 제작 영역이며 이번 묶음에 음원은 없다.

### P3 — 시작과 재도전

첫 설명의 중심은 “같은 색 사공 4명이 모이면 팡!”으로 둔다. PC와 모바일 조작 설명을 상황에 맞게 간결하게 보여준다. 현재 점수·최고 연쇄·최고점과 착지 표시를 유지한다. 게임 종료 후 원인, 이번 점수, 최고 연쇄, 다시 출항 버튼을 보여주는 방향을 권장한다.

## 5. 전달 그림과 사용법

`assets/sagong-atlas.png`: 1254×1254 RGBA PNG. 실제 투명 알파 확인. 네 색 사공, 빈 배, 반짝임을 한 장에 담았다. 색 외에 모자와 원/삼각형/사각형/마름모 기호로 구별한다. 애니메이션 프레임은 아니며 위치·회전·확대·투명도는 코드로 구현한다.

중요: 생성 결과의 배는 가로로 길어서 균등 2×3 셀 경계를 넘는다. 균등 분할하지 말고 `assets/atlas.json`의 개별 source rectangle을 사용한다. 사공 네 명은 동일한 목적지 셀 크기로 그리고 배는 원래 종횡비를 유지한다. 24~40px 실제 게임 크기에서 표정과 기호가 읽히는지 확인할 것.

`assets/mountain-path-background.png`: **우선안.** 1024×1536 RGB PNG. 하단 강, 오른쪽 산길, 정상의 작은 깃발로 구성한 첫 배경이다. 사용자 최신 피드백에 따라 살린다. 중앙 여백 위에 판을 배치하고 필요하면 판 영역에 반투명 단색층을 추가한다. 배경의 산길을 따라 배가 움직이게 하되, 경로와 위험도는 코드로 관리한다. 원화의 강과 깃발이 지나친 크롭으로 사라지지 않게 한다.

`assets/mountain-water-background.png`: **비교용 대안.** 1024×1536 RGB PNG. 영상의 기존 배치와 가까운 상단 산 / 하단 물 구성이다. 사용자가 선택한 우선안을 이 배경으로 임의 대체하지 않는다. 수면은 이미지 상단에서 약 23% 지점이다.

`assets/atlas.json`: PNG에서 가져올 영역과 설명. 직접 `drawImage(image, sx, sy, sw, sh, dx, dy, dw, dh)`로 사용할 수 있다. 좌표는 이미지 실측 크기를 기준으로 정했다.

`PROMPTS.md`: 내장 image_gen으로 만든 최종 프롬프트 원문. 재생성 또는 변형 시 참고한다.

그림은 새 미술 방향의 초안이다. 기존 사공의 둥근 형태·크기와 잘 어울리는지 확인한다. 우선 산길 배경을 사용한 화면에 사공과 배를 배치해 가독성을 검토한다. 생성 PNG는 원본 크기이므로 최종 서비스 반영 전 필요한 해상도로 최적화한다.

## 6. 완료 기준

- 출항 → 낙하 → 이동/회전 → 정착 → 4명 제거 → 중력 → 2연쇄 이상 → 다음 쌍 생성이 정상 동작.
- 대각선만 연결된 4명은 제거되지 않고, 동시에 터지는 그룹은 잘못된 추가 연쇄로 계산되지 않음.
- 배 높이가 기존 규칙과 일치하며 연쇄 도중 성급하게 종료되지 않음.
- 사공 이미지와 논리 셀, 착지 예상 위치가 일치함.
- 벽/바닥 회전, 빠른 입력, 연쇄 중 입력, 재시작 중복 루프를 확인.
- 모바일 탭 회전과 드래그가 중복 발동하지 않고, 버튼과 스와이프가 충돌하지 않음.
- 좁은 화면에서 보드와 조작부가 잘리지 않고, 긴 화면에서도 보드 비율이 유지됨.
- 실제 iPhone Safari / Android Chrome 검증과 데스크톱 viewport 검증을 구분해 보고.
- 자산 누락 시 빈 화면 대신 기존 도형 표현 등으로 대응.
- 배포 단계의 공통 검증은 최신 AGENTS.md를 따른다. 이번 인계만으로 공개 배포하지 않는다.

## 7. 권장 진행 순서

1. 실제 서비스 소스와 현재 규칙 확인.
2. 영상에서 확인되지 않은 연쇄·배 높이·종료를 직접 재현.
3. 사공과 배 그림을 기존 좌표계에 적용.
4. 배 상승·하강 피드백과 짧은 연쇄 연출 보강.
5. 사용자에게 기존 화면 대비 플레이 영상을 보여주고 체감 난이도 조정.

이 인계 작성 시 최신 origin/main을 fetch했고 HEAD와 차이는 0/0이었다. 기존 미커밋 변경과 미추적 파일은 유지했다. 공용 랜딩, 게임 코드, AGENTS.md, 배포 설정은 수정하지 않았다.
