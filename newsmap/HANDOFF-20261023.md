## 확정된 기사 운영

사용자가 10분 주기, 공식 RSS+필요한 기사 도입부, 정확도 우선을 선택했다. 수집 도구는 tools/collect_news.py이며 .github/workflows/update-here-news.yml이 실행한다. 전체 사이트 배포 workflow는 수정하지 않는다. 정기 실행 외에 기존 전체 배포가 성공한 뒤에도 새 데이터로 복구한다.

이전 공개 스냅샷과 ID로 병합하며 최근 30일 범위에서 최대 10,000건을 보관한다. RSS 노출 범위 밖의 전수 수집은 보장하지 않는다. 기사 본문 전체는 배포하지 않는다. 위치가 불명확한 기사는 제외하며 과거 이력 지명과 발신지만으로 배치하지 않는다. 구까지만 확인된 기사는 동네로 내리지 않는다.

8개 RSS 중 지방 whol.xml이 실제 점검에서 HTML을 반환해 실패로 기록됐다. 정상 7개로 수집하되 경고를 남긴다. 최종 로컬 수집에서 531건 확인, 218건 위치 판정, 기존 이력과 합쳐 280건이었다. 실시간 건수는 변한다.

배포 후보 검증 후 기존 서버의 data/articles.js만 원자적으로 교체한다. 공개 파일 해시가 맞지 않으면 이전 기사 파일로 복구한다. 예약 실행과 self-hosted runner 대기는 지연될 수 있다.
