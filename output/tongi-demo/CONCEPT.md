# 통이 활용 재기획 · 2026-11-05

통이의 초기 역할은 ‘뉴스 탐색 길잡이’다. 방문자가 질문을 검색어로 바꾸는 수고를 줄이고, 이미 만든 콘텐츠를 발견하게 한다. 4개 서비스 메뉴는 제거하고 단일 질문 입력으로 시작한다. 현재 구현은 규칙 기반이며 LLM을 호출하지 않는다.

## MAI에서 실제 확인한 것

[매경 MAI](https://mai.mk.co.kr/)의 공개 랜딩은 뉴스·증권·경제교육 에이전트, AI 지식 검색·해설·추천 질문·요약·오디오·퀴즈 등을 소개한다. 이번 확인은 공개 랜딩의 기능 소개이며, 로그인 이후 기능 품질을 검증했다는 의미는 아니다. 통이에 가져올 것은 질문에서 관련 정보로 이어지는 동선과 후속 탐색이다. 기사 데이터·생성 API 없이 요약·실시간 브리핑·범용 튜터까지 제공한다고 표현하지 않는다.

## 가능한 초기 아이디어

| 활용 | 방문자가 얻는 것 | 필요한 데이터와 구현 | 현재 상태 |

| 기사 속 용어 풀이 | 지정된 용어의 뜻을 즉시 확인 | 편집자가 검증한 용어집과 해당 기사 연결 | 후속 후보; 무제한 AI 해설로 표현하지 않음 |

현재 우선순위는 검색어 정리+읽기 길잡이다. 이후에는 계산대로의 실제 입력 항목을 연결하거나 소규모 용어집을 붙이는 것이 현실적이다. 관심사 브리핑은 기사 공급·갱신·개인화 설계가 먼저 필요해 보류한다.

Claude의 독립 기획 반대도 채택했다. 단순한 ‘질문→Google’만으로는 직접 검색보다 효용이 작고 외부 이탈이 생긴다. 후속 최우선은 **편집자가 기사별 탐색 질문을 3~5개 붙이는 큐레이션 인덱스**다. 기사 본문을 검토해 해당 질문과 콘텐츠의 관계를 편집자가 확인한 뒤 추가해야 하며, 지금 구현된 제목·설명 기반 매칭과 구분한다. 아직 이 인덱스가 완성됐다고 보고하지 않는다.

## 공식 검색 연결 실험

- 뉴시스 메인 상단 검색을 실제 조작하면 `POST https://www.newsis.com/search/`, `search_val` 필드로 결과가 열린다. ‘국민연금’ 검색 결과가 실제 표시됨을 확인했다.
- 검색어 포함 외부 GET, 외부 POST 모두 HTTP 200이지만 `정상적인 접근이외의 접속은 불허합니다.` alert와 history.back을 반환했다. HTTP 200만으로 검색 성공을 판단하지 않았다.
- 현재 시안은 `https://www.google.com/search?q=site:newsis.com/view/ + 검색어`로 연결한다. 실제 국민연금 개혁 관련 뉴시스 기사 목록을 브라우저에서 확인했다. Google에 수집된 기사 범위이며 뉴시스 내부의 최신 전체 색인과 같지 않다.
- 공식 검색을 원하는 독자는 검색어 복사 → 공식 홈페이지 상단 검색에 붙여 넣는다. 창에 이 한계를 명시했다. 공식 검색으로 자동 전달되었다고 표현하지 않는다.
- 실서비스 `visual.newsis.com`에서 공식 검색 연계 허용 여부는 별도 확인이 필요하다. 공식 지원 GET 링크나 연동 허용이 확보되면 출구만 교체할 수 있다. 리퍼러 위조·보호 기능 우회·새 서버는 사용하지 않는다.

## 상호작용과 크레딧

처음 3번 연속 클릭하면 ‘아파요 -_-’, 이후 두 번 더 클릭하면 등 돌린 포즈. 이후 클릭·입력·검색·창 닫고 열기로 삐짐이 풀리지 않는다. 좌우로 쓰다듬으면 ‘헤헤 간지러워요’와 함께 복귀한다. 키보드·터치 사용자를 위한 명시적인 쓰다듬기 버튼도 제공한다. 삐져도 검색은 작동한다. 새 뒷모습은 승인된 통이 렌더를 이미지 생성 도구에 참조해 만든 추가 포즈이며 3D 리깅은 아니다.

작은 진입 버튼에는 크레딧을 생략하고, 열린 창 하단에 ‘크리에이티브 디렉터 = 안재현’을 상시 표시한다. PC 340px, 모바일도 내용에 따른 작은 창이며 초기 높이는 약 350px이다. 결과가 늘면 최대 높이 안에서 스크롤한다.
