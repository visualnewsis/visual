2. hero 키보드 교체 (quality-machines.js)
────────────────────────────────────────
기존 buildKeyboard와 같은 API입니다:
  {group, eye, parts:{body,key,cap,spring}, update(state, detail)}
  - state.key / state.travel (lab.js 그대로). 'Fixed switch housing' 이름 유지(기존 테스트 호환).
  - 클릭 가능한 키(Q~M, space)만 userData.action='key:X' → 기존 action()이 [data-key] 버튼을 click.
  - 숫자·기호·Enter·한글 입력도 해당 키가 4mm 눌립니다(추가 동작, 기존 입력 흐름은 그대로).
    예: '각'→R, '가'→K, 'ㄲ'→R, '!'→1, 줄바꿈→Enter.

권장 연결 (기존 export 이름 유지 → mechanics-detail.test.mjs의 buildKeyboard 테스트도 그대로 통과):

  // goodeasy/assets/quality-machines.js 상단 import 구역
  import {buildKeyboardHero} from './models/keyboard-hero.js?v=20261030-keycap1';

  // 기존 39번째 줄 export function buildKeyboard(){...} 전체를 다음 한 줄로 교체
  export function buildKeyboard(){return buildKeyboardHero(T,M);}

  // machineBuilders의 'keyboard':buildKeyboard 는 그대로 둠
  // 이후 quality-stage.js:8 의 quality-machines.js ?v 및 keyboard/index.html 의 quality-stage.js ?v 갱신

또는 옛 함수를 남기려면:
  export const machineBuilders={..., 'keyboard':()=>buildKeyboardHero(T,M), ...};

카메라: model.eye = [2.2, 8, 7.6] (모델이 제공. quality-stage boot()의 stage.setModel(model, model.eye||...) 그대로 사용)
stabilizeStage 사용(기존과 동일) → 키가 눌려도 화면 재맞춤 없음.
DOM이 없으면(Node 테스트) 각인 텍스처 없이도 생성됩니다.

3. (선택) 내부 관찰 상태 — GPT 명세 "외형과 내부 관찰 상태를 구분"
────────────────────────────────────────
mx-switch update에 opt-in 인자 2개를 추가했습니다. 기본값이면 기존 외형 그대로입니다.
  cutaway: 1  → 관찰 카메라 쪽(+x, +z) 하부 하우징 벽, 앞쪽 가이드 채널·클립을 숨겨 접점·스프링을 보이게 함
  capTilt: 라디안 → 키캡 밑면(십자 소켓) 기울기를 직접 지정.
           미지정 시 explode 0.35부터 smoothstep으로 0→0.95rad (소켓이 십자에서 빠지고 판 위로 올라온 뒤에만 기울어짐).
           주의: capTilt를 직접 주면 이 안전 구간을 건너뜁니다. 분해 뷰어(anatomy-models.js)는 키캡/상부 하우징
           오프셋 간격(2.8 vs 2.0)이 좁아서 기울이면 판과 겹칩니다 → 분해 뷰어에는 capTilt를 쓰지 마세요.

예시 A — 페이지 '안쪽 보기' detail에서만 절개 상태 사용 (quality-stage.js draw()의 detailModel.update 호출부):
  detailModel.update?.(kind==='keyboard'?{...(record||state),cutaway:1}:(kind==='camera'?...:record||state),true,now);

예시 B — 연구 01(mx-structure)에 절개 토글을 둘 경우, 해당 상태 객체에 cutaway를 넣어 update로 전달.
         (연구 01의 '펼쳐보기'는 별도 연결 없이 explode 값만으로 키캡이 기울어 소켓을 보여줍니다.)

참고: explode 중 접점 리프는 이제 스템(캠)과의 실제 상대 위치로 움직이며, leaf.userData.closed도 같은 기준입니다
(explode 0에서는 이전과 완전히 동일). quality-switch.js의 LED처럼 closed를 읽는 곳은 그대로 동작합니다.
