직접 실행한 것

첨부한 core 코드와 원래 테스트 6개에, 제가 반례 9개를 더해 Node로 돌렸고 15개 모두 통과했습니다.
추가한 반례: 6000ms와 6001ms 경계, 대기 10초 만료 경계, 대기 중 세 번째 빗나감으로 다시 대기 시작, 대기 중 키 성공 시 초기화, NaN 시간, 320px 폭에서 위치 실패 후 인라인 대체, 극단적으로 좁은 viewport.
상태 로직과 위치 계산에서는 결함을 찾지 못했습니다.

P2 (코드 추론)

안내의 Tab 순서가 멉니다.
안내 요소를 body 맨 끝에 붙입니다. 키보드 사용자가 "어디부터 하지?"를 누른 뒤 Tab을 눌러도 안내의 이동·닫기 버튼으로 가지 못하고, 페이지 전체를 지나야 도달합니다.
재현: Tab으로 도움 버튼에 간 뒤 Enter, 다시 Tab을 눌러 보세요.
수정: 화면 위치는 fixed 그대로 두고, DOM에서만 도움 버튼 바로 뒤에 넣으면 됩니다.
수동 도움을 눌렀는데 아무것도 보이지 않을 수 있습니다.
위치 계산에 실패하면 스크린리더용 live 영역에만 문장이 들어가고, 눈으로 보이는 피드백은 없습니다.
특히 "다음은?" 단계는 대상이 화면 하단에 있는 .hero-next라서, 1280×720에서 아래가 조금만 잘려도 실패할 가능성이 높습니다(추정).
사용자가 직접 요청한 도움이므로 scrollIntoView({block:'nearest'}) 후 표시하거나, 최소한 버튼 옆에 보이는 문구를 띄워야 합니다.
인라인 대체 시 소리 안내가 가려집니다.
인라인 모드는 상태 영역을 visibility:hidden으로 숨기는데, 그 안에 있던 "소리가 납니다" 안내가 함께 사라집니다.
입력 단계 안내는 사용자가 첫 키를 누르기 직전에 뜨므로, 가장 필요한 순간에 소리 경고가 없어집니다. 390px·320px 캡처에서도 소리 안내 대신 통이 문구만 보입니다.

UX 반대

자동 안내 문구 "여기에 한 줄 써보세요."는 입력칸 placeholder와 똑같습니다.
자동 안내가 뜨는 이유는 "케이스를 두 번 눌렀는데 키에 안 맞았다"는 것입니다. 그렇다면 그 실패에 맞는 말이어야 합니다. 예: "키캡 위를 누르거나, 여기에 써도 돼요."
지금 문구는 정보를 더하지 못합니다.

P3

터치 기기에서 말풍선 본문을 탭하면 :hover가 남아 12초 자동 퇴장이 계속 미뤄질 수 있습니다.
도움 버튼을 다시 눌러 닫아도 세션 전체의 자동 제안이 꺼집니다. 의도라면 수용하되 문서에 적어 주세요.

정지 화면 관찰

PC에서 말풍선은 소개 문구와 입력칸 사이의 빈 공간에 들어가며, 원래 조작이나 문구를 가리지 않습니다.
입력칸 강조 윤곽의 대비는 충분합니다.
320px에서도 버튼 줄이 넘치지 않습니다.
