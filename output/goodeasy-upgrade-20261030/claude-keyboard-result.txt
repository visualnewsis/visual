3. 구현 내용 (모델 단위 1 = 10mm, 제조사 CAD 아님)
────────────────────────────────────────
[키캡 — 일반높이, 실측 프로브 값]
- 바닥 외곽 18.0×18.0mm (19.05 피치 − 1.05 간격), 전체 높이 9.5mm, 윗면 12.7×14.0mm(필렛 포함 14.5)
- 측벽 1.25mm, 윗판 두께 1.3mm, 모서리 R1.6(아래)/R1.2(위), 윗모서리 필렛 0.9mm
- 윗면: 원통형 오목 디시 0.7mm (가운데가 낮고 손가락 방향으로 곧음). 평면+둥근 테두리 방식 아님
- 밑면: 빈 셸 + 두꺼운 스커트 테두리 + 둥근 소켓 보스(Ø5.5) 안의 진짜 + 십자 구멍(편측 0.08mm 여유)
  + 보강 리브 4개. 십자 결합 깊이 3.4mm
- 각인: R 왼쪽 / ㄲ 오른쪽 위 / ㄱ 오른쪽 아래. 텍스처가 아니라 디시 곡면 위 0.03mm에 붙은 형상
  (정확한 유니코드 ㄲ·ㄱ 자형을 직접 설계, 다른 문자 없음)
- 분해(explode) 시 키캡이 판 위로 충분히 올라온 뒤(explode 0.35부터) 밑면을 관찰자 쪽으로 기울여 소켓이 보임
[스템·스위치 — 빨간 리니어]
- 십자 결합부 4.0mm(가로대 1.31 / 세로대 1.17mm), 단차 있는 헤드(윗모서리 라운드), 스프링 구멍이 뚫린 두꺼운
  슬라이더 본체, 양측 가이드 날개 + 상부 하우징 가이드 채널 4개, 스프링 중앙축(폴) + 하부 중앙 슬리브,
  캠 다리(기존 캠 곡선 유지) + 캠 받침·외곽 브리지·웹
- 스프링: 실제 튜브 나선을 매번 제자리에서 재계산(눌려도 선재가 납작해지지 않음), 양끝 밀착 감김,
  4mm에서도 코일 간격 > 선재 지름(밀착 없음). 바닥과 스템 구멍 천장에 양끝이 닿음
- 동작 순서 유지: 누름 → 2mm 접점 닫힘 → 4mm 가이드 날개가 바닥 패드에 정확히 닿음 → 손 떼면 스프링 복귀 → 접점 열림
- 택타일 돌기·클릭 부품 추가 없음. 캠이 금속 리프를 밀어 접점 상태를 바꾸는 구조 그대로
- 추가 opt-in 인자: cutaway:1(관찰용 절개: 카메라 쪽 벽·가이드·클립 숨김), capTilt(키캡 기울기 직접 지정)
[hero 키보드 — keyboard-hero.js]
- ANSI 60% 61키, 19.05mm 피치, 행 stagger Tab 1.5u / Caps 1.75u / Shift 2.25u, 스페이스바 6.25u(B 아래)
- 행별 높이·기울기 sculpt(숫자열이 가장 높고 앞줄은 반대로 기울어짐), 모든 키캡 9~12mm, 디시 0.45~0.7mm
- 2벌식 한글 각인(R키: R 왼쪽·ㄲ 오른쪽 위·ㄱ 오른쪽 아래), 수식키 회색
- 입력: 기존 state.key/travel 그대로. 화면 버튼이 있는 Q~M·space만 3D 클릭을 버튼 click으로 전달.
  숫자·기호·Enter·Backspace·한글(음절 분해, 겹자모는 마지막 입력 자모)도 해당 키가 눌림. Delete 등 없는 키는 무반응.
- 정지 이미지로 대체하지 않은 실시간 Three.js 모형. DOM 없는 환경에서도 생성됨(각인만 생략)

4. 함께 고친 기존 결함 (재현 후 수정, 테스트로 고정)
────────────────────────────────────────
- 소켓 윗면이 키캡 디시를 뚫고 올라와 윗면에 십자가 보이던 문제
- 4mm에서 스프링이 선재 두께보다 더 압축되던(코일 관통) 문제
- 3.8~4mm에서 캠 외곽 지지대가 고정 접점 버튼을 관통하던 문제(지지대를 접점 위로 올림)
- 누른 채 분해할 때 리프 탭이 캠을 0.2~0.6mm 파고들고 closed 표시가 실제와 다르던 문제(기존부터 있던 문제)
- (작업 중 발견) 3.6mm 이상에서 상부 하우징 각진 모서리가 키캡 안쪽 둥근 모서리에 닿던 문제 → 판 모서리 R1.2
