01작업 시작 전

  1. 저장소를 최신 origin/main 기준으로 맞춥니다. 내 로컬에 커밋하지 않은 변경이 있으면 먼저 보존합니다.
  2. 루트의 AGENTS.md를 처음부터 끝까지 읽습니다. AI 도구(Codex, Claude 등)를 쓴다면 작업 시작 때 이 파일을 읽게 하세요. Claude는 CLAUDE.md가 자동으로 AGENTS.md를 불러옵니다.
  3. 내가 맡은 폴더와 파일이 무엇인지 메인 관리자(안재현 기자)에게 확인합니다.
우선순위: 메인 관리자의 현재 지시 → 최신 AGENTS.md → 최신 main의 실제 구현 → 개별 파일 → 작업자 판단.

AGENTS.md는 메인 관리자 승인 없이 수정하지 않습니다. 더 나은 방식이 있으면 제안만 합니다.

02권한과 작업 범위

정보구조, 작품 편성과 번호, 공용 랜딩, 디자인 체계, 배포 방향은 메인 관리자가 결정합니다. 다른 작업자는 지정·승인받은 콘텐츠 폴더만 작업합니다.

승인 없이 수정 금지
  • 루트 index.html(VISUAL NEWSIS 메인), editshop/index.html(편집# 랜딩), arcade/index.html(충무로딩 랜딩) 등 공용 랜딩
  • assets/의 공용 헤더·더보기·로고 파일, 공용 SEO·분석 태그
  • .github/의 GitHub Actions와 배포 자동화, sitemap.xml
  • 여러 콘텐츠가 함께 쓰는 데이터 파일(더보기 목록 등)

새 콘텐츠 폴더를 만드는 일과, 그 콘텐츠를 메인·랜딩·더보기에 노출하는 일은 별개입니다. 노출(등록)은 메인 관리자가 직접 하거나 명시적으로 승인한 경우에만 합니다.

03기술 구조

  • 결과물은 HTML, CSS, 순수 JavaScript와 이미지·영상·음원 같은 정적 파일입니다.
  • 각 콘텐츠는 저장소 루트의 자기 폴더에 둡니다. 예: dmz/index.html → https://visual.newsis.com/dmz/
  • 폴더의 index.html을 열면 별도 서버 없이 바로 작동해야 합니다.
  • Next.js, React·Vue·Node.js 서버, API 라우터, 별도 배포 프로젝트를 만들지 않습니다. 빌드 과정이 꼭 필요하면 구현 전에 승인을 받습니다.
  • 자산 경로는 상대경로(images/…, ../assets/…)로 씁니다. 존재하지 않는 URL을 추측해 넣지 않습니다.
  • 폴더명은 영문 소문자와 하이픈으로 짓고, 정하기 전에 관리자와 맞춥니다.
  • backup, old, test 같은 이름만 보고 실서비스 여부를 판단하지 말고 실제 서비스 경로를 확인합니다.

05글로벌 헤더

충무로딩을 뺀 모든 콘텐츠는 공통 헤더를 씁니다. 헤더를 직접 만들지 말고 공용 파일 두 개를 불러오면, 스크립트가 VISUAL NEWSIS / NEWSIS 로고 / 섹션명 + ☰ 구조의 헤더를 그려 줍니다.

<link rel="stylesheet" href="../assets/visual-header.css?v=…">
<script defer src="../assets/visual-header.js?v=…"
  data-section="편집#"
  data-section-href="https://visual.newsis.com/editshop/"
  data-current="editshop"
  data-header-theme="dark"></script>
속성의미
data-section오른쪽에 표시할 섹션명(편집#, 뉴시스템, 한눈에 알아볼지도, 계산대로 등)
data-section-href섹션 랜딩이 실제로 있을 때만 넣습니다. 없으면 생략해 텍스트로만 표시
data-current햄버거 메뉴에서 현재 섹션 표시용 키(editshop, newsystem, calculator 등)
data-header-themedark 또는 light
  • ?v= 값은 최근 발행된 다른 페이지가 쓰는 값을 그대로 씁니다.
  • 작품 번호는 헤더에 넣지 않습니다. 헤더 아래에 메뉴용 두 번째 고정 바를 만들지 않습니다.
  • 햄버거 메뉴 항목은 공용 스크립트가 관리합니다. 페이지에서 따로 메뉴를 만들지 않습니다.
  • 예외: 충무로딩(arcade/)은 자체 상단바를 유지하며 공통 헤더를 넣지 않습니다.

06하단 더보기

기사 하단의 다른 기사 목록은 페이지마다 카드를 새로 만들지 않고 공통 더보기 파일을 씁니다. 현재 작품은 자동으로 빠지고, PC는 좌우 버튼, 모바일은 가로 스와이프로 넘깁니다.

소속불러올 파일위치
편집#editshop-carousel.css + editshop-carousel.js최하단 편집# 브랜드 배너 바로 위(스크립트가 자동 배치)
뉴시스템visual-stories-carousel.css + newsystem-carousel.js본문과 엔딩이 끝난 뒤
그 밖의 비편집 기사visual-stories-carousel.css + visual-stories-carousel.js본문·관련기사·엔딩이 모두 끝난 뒤 최하단
 
<script defer src="../assets/editshop-carousel.js?v=…" data-current="내폴더명"></script>

더보기 목록에 새 작품을 추가하는 것은 공용 데이터 수정이므로 관리자 승인 후에 합니다. 공용 더보기 파일을 바꾸면 그 파일을 쓰는 모든 페이지의 ?v=를 함께 올립니다.

07작품 번호

  • VISUAL NEWSIS 메인은 전체 발행 순서대로 STORY 001부터 매깁니다.
  • 편집#은 편집# 작품끼리 #001부터 따로 매깁니다.
  • 예: 전체 20번째이면서 편집# 14번째 작품은 메인 STORY 020, 편집# #014입니다.
  • 번호는 추정하거나 빈 번호를 채우지 말고, 현재 발행 목록과 관리자 지시로 확정합니다.

08이미지와 출처

사진 출처

사용하는 모든 사진에 출처를 표기합니다. 예: ⓒ뉴시스 OOO 기자, (사진=OO 제공). 참고용 사진처럼 기사 현장과 다른 사진은 그 사실도 함께 밝힙니다.

포털 송고용 이미지 첫 장

  • 포털 미리보기·대표 썸네일로 쓰이므로 가로형(4:3 또는 5:3)으로 만듭니다. 세로형·정사각형은 첫 장으로 쓰지 않습니다.
  • 원본 사진 중심으로 구성하고, 제목이나 문구를 합성한 표지로 만들지 않습니다. 글자가 들어간 그래픽은 두 번째 장부터 씁니다.
  • 작게 줄거나 일부가 잘려도 핵심 인물·주제가 보이도록 여백을 둡니다.

사이트 썸네일

  • 기본 크기는 360 × 240px입니다.
  • 모바일에서 아래쪽이 잘리므로 하단 48px(y=192~239)에는 배경만 둡니다.
  • 글자·얼굴·로고 등 주요 요소는 x=12~348, y=12~192 안에 넣습니다.

공유 이미지

og:image는 1200 × 630px로 만들고 콘텐츠 폴더 안에 둡니다.

09Git과 배포

main에 push하면 GitHub Actions가 자동으로 실서버에 배포합니다. 자동화도 main에 커밋하므로 아래 순서를 지킵니다.

  1. 작업 전 git fetch로 최신 origin/main을 반영합니다.
  2. 내 담당 파일만 git add 합니다. 무관한 변경, 원본 사진, 임시 파일은 스테이징하지 않습니다.
  3. push 직전에 원격 변경을 다시 확인합니다.
  4. 배포가 끝나면 실제 URL에서 반영 여부를 확인합니다.
하지 않는 것
  • git reset --hard, 강제 checkout, force push, 다른 사람의 미커밋 변경 삭제
  • 충돌 시 한쪽 버전만 골라 덮어쓰기. 양쪽을 비교하고, 판단이 필요하면 관리자에게 보고
  • 같은 공용 파일을 다른 작업자와 동시에 수정
  • API 키·토큰·비밀번호를 저장소에 평문으로 넣기
  • 배포 workflow 수정·삭제(승인 필요)

저장소는 공용 계정을 쓰므로 커밋 작성자만으로 실제 작업자를 구분할 수 없습니다. 커밋 메시지에 무엇을 바꿨는지 분명히 적어 주세요.

CSS·JS 파일을 고치면 그 파일을 불러오는 ?v= 값을 올려 브라우저 캐시를 갱신합니다.

10배포 전 점검

  • HTML과 JavaScript에 문법 오류가 없다
  • 모든 JSON-LD 블록이 파싱된다
  • 제목·설명·canonical·OG·Twitter가 이 페이지 기준으로 바뀌었다
  • GA 태그가 정확히 한 번 들어 있다
  • 파비콘과 글로벌 헤더가 나온다(충무로딩 제외)
  • 이미지·영상·음원·내부 링크가 실제 서비스 경로에서 열린다
  • 데스크톱과 모바일(iPhone Safari, Android Chrome)에서 화면을 확인했다
  • 사진 출처가 모두 표기돼 있다
  • 내 담당 범위 밖의 파일이 변경되지 않았다

11완료 보고

작업을 마치면 메인 관리자에게 다음을 알립니다.

  • 수정한 내용과 파일 목록
  • 건드리지 않고 유지한 영역
  • 수행한 검증. 실제 기기에서 확인했는지, 화면 크기만 바꿔 확인했는지 구분
  • 남은 문제나 확인이 필요한 점

작업 범위가 불분명하거나 공용 파일 수정이 필요해 보이면, 진행하기 전에 먼저 물어봐 주세요.
