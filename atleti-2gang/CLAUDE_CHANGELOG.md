## 2. 구현한 것 (BUILD_SPEC 항목별)

- **A. 경험 목표**: ① LEE를 드래그하면 4~6명이 순서대로 반응 → ② 둘 다 넣으면 12/11이 되고 한 명을 빼야 함 → ③ 질문 전환(QUESTION FLIP) → ④ 결과 카드에 사용자의 선택이 그대로 남음.
- **B. 첫 화면**: 히어로 높이 `clamp(460px,62svh,720px)`. 390×844(모바일)에서는 히어로 바로 아래로 전술판 상단과 11/11 카운터가 보이고, 1440×900(데스크톱)에서는 전술판이 y=745px부터 보여 한 번 스크롤하기 전에 드러난다.
- **C. 전술판 엔진**: `STATES` 객체(RIGHT_DAVID / RIGHT_JULIAN / TEN_DAVID / SS_DAVID / DAVID_JULIAN_LEE / REAL_MODE)의 x/y 값을 `Board.render()`가 그린다. 위치를 흩어진 인라인 스타일로 박아두지 않았다.
  - 반응 순서: 원인 선수 0ms → 가장 가까운 동료 100ms → 중원 200ms → 나머지 260ms → 패스·침투선 320ms → 공간 빗금 450ms. 움직인 선수마다 이동 궤적 잔상과 파동 링이 붙고, 아래 체인 칩(`LEE 이동 → 가장 가까운 동료 → 중원 → 패스길 → 공간`)이 같은 타이밍에 켜진다.
  - 상태를 빠르게 바꾸면 이전 타이머를 모두 취소하고, CSS transition은 현재 위치에서 다시 이어진다.
  - 선수 레이어는 크기 0인 요소를 컨테이너 쿼리 단위(`cqw/cqh`)로 옮긴다. 미지원 브라우저용 `@supports` fallback이 있다. 전술판 크기의 레이어를 수십 개 합성하는 문제를 피하려는 조치다.
- **D. 드래그**: LEE에만 `touch-action:none`과 pointer capture를 적용했다. 전술판의 다른 곳을 쓸면 페이지가 정상적으로 스크롤된다. 드래그 중에는 LEE만 따라오고, 가장 가까운 전술 구역(우측 안쪽 / 중앙 10번 / 세컨드 스트라이커)이 버튼처럼 보이지 않는 점선 고스트 링으로만 나타난다. 손을 떼면 가장 가까운 유효 상태로 붙는다. LEE를 탭하면 다음 자리로 바뀐다.
  - JULIÁN 모델에는 `RIGHT_JULIAN`만 있다. JULIÁN을 고른 채 중앙이나 투톱에 놓으면 우측 안쪽으로 붙고, 그 이유를 안내 문구로 보여준다(없는 시나리오를 만들지 않음).
- **E. 렌즈**: 전체 / 공간 / 패스. 공간 렌즈는 선수 .45, 빗금 1.0, 선 .15. 패스 렌즈는 빗금 .1, 선수 .7, 선 1.0. 측정값이 명세와 일치한다. 점유 영역은 히트맵처럼 보이지 않도록 **빗금 + 윤곽선 + 텍스트 라벨**로만 그렸다(그라데이션·숫자 없음).
- **F. 근거 UI**: 전술판마다 `근거 강 / 중 / 가설` 배지를 둔다. 누르면 출처 ID와 한 줄 설명이 뜨고 `전체 출처 보기`로 드로어의 해당 출처로 이동한다. 가설 상태에는 패널과 드로어에 `전술 시나리오` 태그를 반드시 붙인다. 본문에 흩어질 출처는 하단 `근거·방법론` 드로어(상태별 근거표, S01~S11 전체, 사진 목록)로 모았다.
  - 신뢰도는 HIGH-MED→강, MED·MED-LOW→중, LOW-MED·LOW→가설로 매핑했다. 상태값이 EDITORIAL_HYPOTHESIS / EDITORIAL_SCENARIO / PUZZLE_HYPOTHESIS이면 `전술 시나리오`로 표시한다.
- **G. 12/11**: `둘 다` → JULIÁN이 들어오며 500ms freeze(채도 낮춤) → 전술판 zoom-out(.93) → 카운터 12/11(빨강·흔들림) → 700ms 뒤 `한 명이 많습니다. 누구를 뺄까요?`. 이때 BAENA·GIULIANO·BARRIOS·HJULMAND만 깜빡이고 나머지는 흐려진다.
  - 선수를 직접 탭하거나 옆 패널의 기능 버튼 3개(키보드 대체)를 누르면, 뺀 선수는 사라지며 벤치 칩(`포기한 기능 · …`)으로 옮겨지고 나머지가 순서대로 재배열된다. 카운터는 11/11(초록)로 돌아온다.
  - 문구는 COPY_DECK의 SACRIFICE를 그대로 썼고 '방출·탈락'이 아니라 '기능'으로 표현했다.
- **H. REAL MODE**: `나의 AT / REAL` 상대 칩. REAL은 5단계 전술 해설도이며 재생·이전·다음 버튼이 있다: ① 레알의 왼쪽(빗금 구역) → ② 푸빌-요렌테-줄리아노 오른쪽 통로 → ③ 줄리아노 질주 → PK → ④ 코케 투입 뒤 요렌테가 RB로 내려가고 줄리아노가 다시 오른쪽을 달림 → ⑤ 데이비드 마무리.
  - LEE는 반대편(약한 쪽)에 고정해 두고 인과 애니메이션을 연결하지 않았다. 상단 카피는 `상대가 바뀌면, 같은 자리의 의미도 바뀝니다.` 그대로다.
  - 상대 선수는 이름 없는 빈 원으로만 표시했다.
- **I. 접근성·성능**: `prefers-reduced-motion`을 지원한다(모든 전환 즉시 적용, 반복 애니메이션·패럴랙스 끔). 키보드로는 LEE를 방향키(↑ 투톱 / ← 중앙 / → 우측)나 Enter로 옮길 수 있고, 별도 `LEE 위치` 버튼 그룹과 희생 기능 버튼도 있다. 선은 모두 SVG이고 canvas는 쓰지 않았다. 외부 라이브러리가 없다.
  - 아바타 슬롯은 `ASSETS.avatars`에서 선수별로 켜고 끌 수 있다(현재 LEE·BAENA만 사진 사용).
- **최종 결과 카드**: `당신의 AT — 이강인 {role} / 공격 {front} / 살린 기능 {gain} / 포기한 기능 {cost} / 근거 수준 {confidence}`. 사용자가 실제로 고른 값이 모두 반영되고, 작은 전술판으로 최종 배치를 다시 그린다. 공유(navigator.share, 미지원 시 클립보드 복사)와 `처음부터 다시`(전체 초기화 후 ①로 이동)를 지원한다.
- **엔딩**: `REAL · BARÇA · ATLETI / 2강 IN / 이강인을 움직이면 AT의 답도 움직입니다. / 시메오네가 풀어야 할 퍼즐은 이제 시작됐습니다.` 사진 4장이 퍼즐 조각처럼 모인다.
- **VISUAL NEWSIS 공통**: 공용 글로벌 헤더(`visual-header.js`, 편집# 섹션, 다크 테마), 편집# 더보기 캐러셀(`editshop-carousel.js`, 브랜드 배너 바로 위로 자동 배치), 편집# 브랜드 배너(editor-note), 푸터를 넣었다.

    - 패널마다 '확인된 것 / 해석한 것'을 한 줄씩 붙였다. 중앙 10번과 세컨드 스트라이커는 이제 '보도 + 기자 해석'으로 표시된다.
    - 드로어 표에는 기획 단계 근거 수준을 괄호로 남겼다.
  - **핵심 체험으로 가는 길 단축**
    - 직접 해보기 1 바로 아래에 "그럼 데이비드와 훌리안을 둘 다 넣으면?" 이동 버튼을 넣었다.
    - 챕터 사진 섹션 높이를 줄였다(TRUE 9는 92에서 62svh로, FIRST WOW는 72svh, 오사수나는 70svh).
  - **모바일 변화 강조**
    - 배치를 바꿀 때마다 가장 중요한 변화 한 줄을 경기장 위에 크게(15px, 굵게) 띄운다. 예: "이강인이 가운데로 가자 바에나와 활동 범위가 겹칩니다".
    - 선수 이름 글자는 8.5px에서 10px로, 공간 라벨도 키웠다.
  - **용어·번호**
    - 이강인 자리 버튼에 역할 설명을 붙였다(오른쪽에서 안으로 좁혀 연결 / 가운데서 패스 뿌리기 / 공격수 바로 뒤).
    - 선수 이름표와 최전방 버튼을 한글로 바꿨다. '박스 기준점'은 '골문 앞 기준점'으로 바꿨다.
    - 체험 번호 ①·②는 '직접 해보기 1·2·3'으로 바꿔, 기사 챕터 번호 01~07과 구분했다.
  - **엔딩**: 설명 문단("이강인이 자리를 옮기자…")을 빼고, 독자가 **내려놓은 것**을 크게 보여주는 문장을 엔딩의 중심에 뒀다. 예: "이강인을 중앙 10번에 두고 데이비드와 훌리안을 세운 당신은 공격을 풀어줄 선수 한 명을 내려놓았습니다". '둘 다'를 한 뒤 아직 고르지 않았으면 고르러 가는 링크를 보여준다.
