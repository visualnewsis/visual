# 사진 ↔ 지도 전환 보간 자산

2026-10-05, 내장 image_gen 도구로 기존 자산을 참조해 만든 연출용 중간 그림이다. 실제 DMZ 현장 사진이나 실제 지리 좌표를 재현한 자료가 아니다. 원본 실제 사진과 기존 3D 지형은 유지한다.

## 저장 파일

- `web/hero-between-detail-v1.webp`: 실제 사진 → 기존 해석 그림 사이. 넓은 파노라마의 세로 크롭 선명도를 위해 모바일에서도 원본 폭을 사용.
- `web/hero-between-approach-v1.webp`: 기존 해석 그림 → 첫 상승 그림 사이.
- `web/hero-between-relief-v1.webp`: 첫 상승 그림 → 입체 지도 그림 사이.
- `web/hero-between-map-v1.webp`: 입체 지도 그림 → 기존 렌더러의 첫 프레임 사이.
- approach, relief, map의 `-800.webp`는 모바일 전송용 축소본이다.

진입·귀환이 같은 자산, 같은 스크롤 상태 함수, 같은 crop을 공유한다. 신규 그림에는 글자·헤더·UI를 넣지 않는다.

## 지형 정합과 렌더링

`js/image-morph.js`는 그림별 능선·도로·강의 굽이를 기준점으로 삼아 두 그림을 같은 중간 위치로 변형한다. 화면 전체를 동시에 반투명하게 겹치지 않고 지형의 세부 표현이 부분적으로 걷히도록 합성한다. 기존 Three.js 렌더러에 작은 화면 메시 하나를 사용하며 별도 WebGL context나 라이브러리는 추가하지 않는다.

최종 MAP은 실제 기존 3D scene의 첫 카메라를 캡처한다. 이어지는 카메라의 투영 좌표를 다시 사용해 MAP의 기준점을 보정한다. 사진이 화면을 완전히 덮는 동안에는 뒤의 3D를 매 프레임 그리지 않는다. 모바일 전용 입체 지도 그림은 별도의 기준점을 사용한다.

## 최종 프롬프트 세트

공통: 기존 참조 그림의 산, 강, 호수, 바다, 좌우 도로와 횡단 도로의 관계를 유지한 하나의 선명한 프레임. 중복 윤곽·이중 노출·안개로 가린 전환 금지. 올리브·회녹색의 절제된 지형 해석. 화면 UI와 글자 없이 생성.

1. detail: 실제 사진과 기존 해석 그림의 약 40% 지점. 실제 사진의 카메라, 지평선, 산, 호수, 해안, 도로를 고정. 현실의 질감을 일부 걷어내되 같은 장소의 사진으로 읽히게 유지. 넓은 2.61:1 파노라마.
2. approach: 해석 그림과 첫 상승 그림 사이의 반쯤 올라간 카메라. 산은 상단 1/3, 바다는 오른쪽, 호수는 위 중앙, 강은 왼쪽 중앙, 좌우 도로와 하단 1/4의 횡단 도로. 회전 없이 앞으로 들어가는 1440×900 풍경.
3. relief: 첫 상승 그림과 입체 지도 그림 사이. 위쪽 해안은 멀어지고 지형이 부드러운 독립 relief로 읽히기 시작. 왼쪽 중앙의 강, 아래 1/3의 횡단 도로, 중앙 민트 선과 기존 랜드마크 보존. 1440×900.
4. map: 기존 입체 지도 그림과 기존 3D 렌더러의 최초 카메라 프레임 사이. 공유하는 강·도로를 기준으로 지형을 제자리에서 단순화. 옅은 회녹색 배경. 참조 스크린샷의 헤더, 모든 라벨·글자와 UI 제거. 회전 없이 1440×900.

생성 PNG의 크기 조정과 WebP 압축만 Pillow로 처리했다. 전환 시점·확대·위치·합성은 순수 JavaScript/CSS가 담당한다.
