# GPT 디자인 의뢰 02 · 버튼·메뉴·관찰 조작계

크리에이티브 디렉터 = 안재현. VISUAL NEWSIS ‘굳이구지’ 피아노 콘텐츠의 실제 작동하는 관찰 UI를 디자인해 주세요. 첨부한 피아노 관찰 시안의 분위기를 유지하면서 버튼과 메뉴를 구현 가능한 상태별 컴포넌트로 완성하는 의뢰입니다.

## 범위와 경험

첫 화면은 작은 굳이구지 표기, ‘자, 건반을 눌러볼까요?’, 실제 연주 가능한 건반입니다. 시작 버튼 없이 바로 연주합니다. 이번 의뢰의 재생 버튼은 **두 번째 단계의 관찰 재생**에만 해당합니다. 첫 연주 앞에 시작 절차를 추가하지 마세요.

체험 → 방금 연주한 음의 내부 관찰 → 브라우저 구현 과정 순서입니다. 이전 연주 음·누른 시간·페달 상태가 관찰로 이어집니다. 시리즈 랜딩, 실험 카드, 과도한 브랜드 소개는 이번 범위가 아닙니다.

첨부 `7d7ae122-6ddb-425e-8587-17dae9f0cdb9.png`는 관찰 화면의 시각적 목표입니다. 이미지 속 모든 버튼을 무조건 복제하라는 뜻은 아닙니다. 필요한 기능을 판별하고 빠진 상태를 설계해 주세요.

## 설계할 조작

- 관찰 재생/일시정지/처음부터. 연주하지 않은 초기 상태와 재생 완료 상태 포함.
- 작동 단계 타임라인: 건반 누름, 해머 이동, 타현, 해머 이탈, 진동, 손 뗌·댐퍼 상태. 드래그 및 키보드 조작.
- 관찰 속도 0.25×, 0.5×, 1×, 2×. 실제 타건과 느린 관찰의 차이를 혼동시키지 말 것. 무음 관찰인지 원속도 소리를 덧붙이는지 명확히 결정할 것.
- 조립/분해 관찰과 복귀. 작동 재생과 분해를 동시에 조작할 때의 상태 규칙.
- 기본 시점·측면·사선·선택 부품 확대·시점 초기화.
- 부품 선택·라벨 표시/숨김. 화면이 라벨로 가득 차지 않게 할 것.
- ‘직전 연주 음’과 ‘별도로 고른 관찰 음’의 구분. 음을 바꿀 때 사용자의 실제 연주 기록을 덮어쓰지 않을 것.
- 서스테인 상태 확인과 관찰 결과의 분기.
- 전체 화면, 지원하지 않는 환경의 대안, 모바일 가로 보기 필요 여부.
- 첫 연주로 돌아가기, 제작 과정으로 이동하기.

모든 기능을 같은 우선순위로 늘어놓지 마세요. 주 조작은 항상 보이고 보조 조작은 필요한 곳에서만 펼쳐집니다. 검색이나 존재하지 않는 메뉴를 장식으로 추가하지 마세요.

## 원하는 산출물

1. 데스크톱 조작계의 실제 크기 배치 시안과 모바일 세로 화면의 배치 시안.
2. 버튼·아이콘·슬라이더·세그먼트·메뉴·툴팁의 확대 컴포넌트 시트. 기본, hover, focus, pressed/selected, disabled, loading, error 상태 포함.
3. 크기, 간격, 색상, 글꼴, 선 두께, 아이콘 규격, 대비값을 적은 디자인 토큰 표.
4. 행동 → 상태 변화 → 화면 피드백을 적은 인터랙션 명세와 상태 전이표.
5. 모바일 터치와 키보드 접근성, 스크린리더 이름, 포커스 이동·복귀 규칙. 모바일 주요 터치 영역은 44px 이상을 기준으로 설계.
6. Codex가 그대로 구현할 수 있는 SVG 아이콘 또는 도형 명세와 CSS 수치. 실제 파일로 제공 가능하면 함께 제공.

과장된 네온이나 게임 HUD 대신 흑연색 배경·절제된 따뜻한 강조색·또렷한 조작계가 필요합니다. 모형을 가리는 유리 카드와 긴 메뉴를 피하세요. ‘크리에이티브 디렉터 = 안재현’은 크레딧에 절제해서 배치합니다. 장식용 버튼을 완성된 기능처럼 제시하지 마세요.
