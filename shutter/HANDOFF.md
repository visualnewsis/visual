# 탐구생활 · 카메라 작업 인수인계

작성: 2026-10-22~23 KST. 이 파일은 회사 PC에서 이어서 작업하기 위한 현재 상태 기록이다. 프로젝트 정책은 저장소 루트의 최신 `AGENTS.md`를 따른다.

## 저장소와 서비스

- 저장소: https://github.com/visualnewsis/visual
- 공개 주소: https://visual.newsis.com/shutter/
- 작업 폴더: 저장소 루트의 `shutter/`
- 디자인 구현 커밋: `96cd00ab823cb1712157825e6b2e462e51031874`
- 공개 배포 확인: 진행 중. 아래 상태를 확인한 뒤 완료로 갱신한다.
- 실행 방식: 정적 HTML·CSS·순수 JavaScript. 설치나 빌드가 필요 없다. 저장소 루트를 정적 서버로 열고 `/shutter/`로 접속한다. 별도 서버 애플리케이션을 만들지 않는다.

## 확정된 디자인 방향과 현재 구현

서비스명은 **탐구생활**, 첫 주제는 **카메라**다. ‘슬기로운’은 표지·검색 문구·공유 이미지에서 제거했다. 옛 탐구생활 교과서 표지의 활자·여백·큰 도판 비례를 참고한 교과서형 A안을 구현했다. 누런 책등·낙서·도장 장식은 걷어냈다.

- 바탕 `#F7F3EA`, 실험 패널 흰색, 기본 글자 `#1A1A1A`, 조작 강조 `#2F6BFF`.
- 서비스 제목은 기존 Noto Serif KR의 인상을 유지하고 PC 64px, 모바일 48px를 기준으로 조정했다. 본문·조작부는 Noto Sans KR이다.
- PC: 왼쪽 약 37%는 주제·소개, 오른쪽 약 63%는 첫 질문·실제 카메라 모형·분해 슬라이더다. 모바일은 한 열이며 소개를 한 문장으로 줄였다.
- 첫 질문은 ‘무엇이 들어 있을까요?’. 별도의 큰 도입 표지로 체험을 아래로 밀지 않는다.
- 카메라는 콘셉트 대체 이미지가 아니라 원래의 실제 조작 모형을 사용한다. 선택된 부품에는 버튼과 같은 파란 테두리·주석이 표시된다. 부품 자체의 색은 설명과 일치하도록 유지했다.
- 차례는 전체 구조 / 렌즈 / 조리개 / 셔터 / 센서 / 사진 실험의 여섯 단계다. 여기의 01~06은 탐구 순서이며 VISUAL NEWSIS 발행 번호가 아니다.
- 탐구생활은 편집# 소속이 아니다. 편집# 브랜드 배너·더보기 문법을 다시 넣지 않는다.
- 공용 글로벌 헤더 구조·파일, 공용 랜딩, 다른 콘텐츠와 배포 자동화는 이번 작업에서 수정하지 않았다.

## 기능과 모형의 가정

분해·회전·부품 선택·빛 경로 표시, 렌즈 초점, 조리개, 선막·후막, 전자셔터 왜곡, 베이어 센서 색 복원, 노출 촬영 네 장 비교와 관찰 기록이 있다.

일반화된 미러리스 카메라 개념 모형이며 특정 제품의 실측 설계가 아니다. 렌즈 실험은 초점거리 60mm의 얇은 렌즈, 조리개 실험의 지름 표시는 초점거리 50mm 기준이다. 셔터막의 센서 통과시간은 4ms로 가정한다. 센서는 RGGB 샘플링과 간단한 주변 화소 보간이다. 본문의 가정·한계 설명을 지우지 않는다.

관찰 기록은 사용자가 저장 버튼을 누를 때 브라우저 localStorage에만 저장된다. 키는 `visual-newsis:tangulife:camera:observation`이며 서버로 전송하지 않는다.

## 검증한 내용

- 저장소 필수 검사 `.github/scripts/check_visual_site.py`: 20개 서비스 페이지 통과.
- `node --check shutter/camera.js` 통과. JSON-LD 파싱, 상대 자산 경로, 중복 ID, 공유 이미지·아이콘 크기를 확인했다.
- 기존 Google 추적 로더·config는 각 한 번이며 유지했다. 검색 수집은 허용 상태다. 기존 사이트맵에 `/shutter/`가 포함돼 있다. 실제 검색엔진 노출 시점은 별도다.
- PC 1440px에서 분해 슬라이더 하단 약 701px. 390px 모바일에서는 약 657px, 320px에서는 약 618px다. 첫 화면에서 모형과 분해 조작부가 보이고 가로 넘침이 없다.
- 부품 버튼·슬라이더·초기화 버튼은 44px 이상의 조작 영역이다. 글로벌 NEWSIS 로고의 뷰포트 중앙 정렬도 확인했다.
- 분해·키보드 회전·부품 선택, 렌즈 초점 맞추기, f/16 광량, 1/8000초 셔터 재생, 센서 색 복원, 촬영 비교를 확인했다. 브라우저 오류·경고 없음.
- 위 화면 검증은 Chromium의 CSS viewport 검증이다. 실제 iPhone Safari·Android Chrome 기기 검증은 아직 하지 않았다.

## 다음 작업자가 시작할 순서

1. 현재 checkout과 branch, 미커밋 변경을 확인하고 안전하게 보존한다. 최신 `origin/main`과 `AGENTS.md`를 확인한다. 이 PC의 이전 checkout에는 다른 콘텐츠의 작업이 많이 남아 있었으므로 과거 폴더를 통째로 덮어쓰지 않는다.
2. 공개 페이지와 `shutter/index.html`, `textbook.css`, `camera.js`를 읽고 현재 A안을 기준으로 삼는다. 원래의 큰 노란 책 표지로 되돌리지 않는다.
3. 저장소 루트에서 로컬 정적 미리보기를 연다. Python이 있으면 `python -m http.server 8767 --bind 127.0.0.1` 후 `http://127.0.0.1:8767/shutter/`로 접속할 수 있다. 사용 가능한 도구를 먼저 확인하고 설치·프레임워크 도입 없이 실행한다.
4. 이후 디자인 세부 조정은 사용자의 다음 지시를 받아 진행한다. 별도 지시가 없으면 임의로 새로운 개편을 시작하지 않는다. 실제 기기 점검과 상단·본문의 세부 비례 다듬기가 남은 검토 항목이다.
5. 수정 후 기존 실험 기능과 PC·모바일을 확인하고, 담당 파일만 커밋한다. 배포가 요청되면 기존 main 기반 자동 배포를 사용하고 실제 공개 주소를 검증한다.
